# NetBird 生产环境优化方案

**适用环境：** `netbird.flaship.org` · 主站 `10.20.9.49`（新加坡 VPC）· Traefik + `netbird-server:dev` · 多区域 Router（JP/HK/TW/MY/OCI）· 国内 Mac 客户端  

**目标：** 降低跨境延迟，避免数据面全部绕道新加坡主站内嵌 Relay；提升公网 Router P2P 成功率；收紧错误 Exit/DNS 策略。

**相关文档：**

- [ROUTER-RELAY-EDGE-DEPLOYMENT.md](./ROUTER-RELAY-EDGE-DEPLOYMENT.md) — 边缘 Relay/Router 技术细节
- [MULTI-REGION-RELAY-OPTIMIZATION.md](./MULTI-REGION-RELAY-OPTIMIZATION.md) — OCI/AWS 防火墙、NAT、Docker P2P
- [HA-DEPLOYMENT.md](./HA-DEPLOYMENT.md) — Relay 水平扩展摘要

## 1. 现状诊断

### 1.1 当前架构

| 组件 | 位置 | 说明 |
|------|------|------|
| 控制面 | `10.20.9.49` / `netbird.flaship.org` | Traefik :443 → dashboard + netbird-server |
| Relay/STUN | **主站内嵌** | `stunPorts: 3478`，`3478:3478/udp` 映射 |
| LDAP | `10.20.9.49:389` | `config.yaml` 已配置 |
| 存储 | SQLite | `~/netbird` |

### 1.2 典型问题（`netbird status -d`）

| 现象 | 影响 |
|------|------|
| 多数海外 Router **Relayed**，ICE `-/-` | 流量经 `rels://netbird.flaship.org:443` |
| Mac 对 `aws-8237-jp` 挂 **`0.0.0.0/0` Exit** 且该 Peer Relayed | 全网流量：Mac → 新加坡 Relay → 日本，极慢 |
| `tw-office` / `aws-1718-my` **P2P** | 正常（~50–80ms） |
| DNS probe failed（1.1.1.1 / 8.8.8.8） | 国内解析差 |
| Dashboard Docker 安装命令为 **bridge** | 公网 Router P2P 失败 |

### 1.3 瓶颈路径

```text
优化前：
Mac（国内）
  → rels://netbird.flaship.org:443（新加坡 10.20.9.49）
  → 日本/香港 Router（Relayed）
  → 目标内网

优化后：
Mac（国内）
  → rels://relay-jp.flaship.org:443（日本）
  → Router / 内网
  或 P2P → 54.95.171.5:51820（aws-8237-jp 修正后）
```

## 2. 目标架构

```text
┌─────────────────────────────────────────────────────────────┐
│ 新加坡 10.20.9.49 · 仅控制面（不改 Traefik 443 用途）           │
│ netbird.flaship.org → Traefik → dashboard / netbird-server   │
│ config.yaml：外部 relays + stuns，Relay: false                 │
└───────────────────────────────┬─────────────────────────────┘
                                │ Management / Signal
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
┌───────────────┐       ┌───────────────┐       ┌───────────────┐
│ relay-jp      │       │ relay-hk      │       │ relay-tw      │
│ .flaship.org  │       │ .flaship.org  │       │ .flaship.org  │
│ :443 / :3478  │       │ 同上          │       │ 同上          │
│ + Router      │       │ + Router      │       │ + Router      │
│ (host 网络)   │       │ (host 网络)   │       │ (host 网络)   │
└───────────────┘       └───────────────┘       └───────────────┘
```

**原则：**

- 主站 **不**部署区域 Relay（443 已被 Traefik 占用）。
- 边缘 `NB_AUTH_SECRET` = 主站 `config.yaml` 的 `authSecret`（勿重新生成）。
- 边缘文件在 **`/opt/netbird-edge`** 自建，**不修改**仓库 `deploy/docker-compose.yml`。

## 3. 实施阶段总览

| 阶段 | 内容 | 影响 |
|------|------|------|
| **A** | 主站 `config.yaml` + `docker-compose.yml` | 需重启 compose；客户端重连 |
| **B** | JP/HK/TW 部署区域 Relay | DNS + 新 VM/现有 EC2 |
| **C** | 修正公网 Router（Docker host + SG） | P2P |
| **D** | Mac Exit / DNS / 路由策略 | 体感延迟 |
| **E** | 验收 | — |

**推荐时间线：**

1. **第 1 天**：DNS → 部署 3 台 Relay（B）→ 主站改造重启（A）  
2. **第 2 天**：日本 Router 修正（C1）+ Mac 取消 Exit（D）  
3. **第 3 天**：HK Router、监控、版本规划  

**禁止：** 在生产机执行 `./getting-started.sh`（会覆盖配置）。

## 4. 阶段 A：主站改造（`10.20.9.49`，`~/netbird`）

### 4.1 备份

```bash
cd ~/netbird
cp config.yaml config.yaml.bak.$(date +%Y%m%d)
```

### 4.2 修改 `config.yaml`

在现有 `server:` 中**保留** `auth`（含 LDAP `10.20.9.49:389`）、`reverseProxy`（`172.30.0.10/32`）、`store`，**增加** `stuns` / `relays`，**注释** `stunPorts`：

```yaml
server:
  listenAddress: ":80"
  exposedAddress: "https://netbird.flaship.org:443"

  stuns:
    - uri: "stun:relay-jp.flaship.org:3478"
      proto: "udp"
    - uri: "stun:relay-hk.flaship.org:3478"
      proto: "udp"
    - uri: "stun:relay-tw.flaship.org:3478"
      proto: "udp"

  relays:
    addresses:
      - "rels://relay-jp.flaship.org:443"
      - "rels://relay-hk.flaship.org:443"
      - "rels://relay-tw.flaship.org:443"
    secret: "<与现有 server.authSecret 完全相同>"
    credentialsTTL: "24h"

  authSecret: "<保持现有值>"

  # stunPorts:
  #   - 3478

  metricsPort: 9090
  healthcheckAddress: ":9000"
  logLevel: "info"
  logFile: "console"
  dataDir: "/var/lib/netbird"

  auth:
    issuer: "https://netbird.flaship.org/oauth2"
    # ... 现有 signKeyRefresh、dashboardRedirectURIs、owner、connectors 全部保留 ...

  reverseProxy:
    trustedHTTPProxies:
      - "172.30.0.10/32"
    trustedPeers:
      - "172.30.0.0/16"

  store:
    engine: "sqlite"
    encryptionKey: "<保持现有值>"
```

### 4.3 修改 `docker-compose.yml`

在 **`netbird-server`** 服务中**删除**：

```yaml
    ports:
      - '3478:3478/udp'
```

**不修改：** traefik、dashboard、labels、网络 `172.30.0.0/24`。

### 4.4 重启与验证

```bash
docker compose down
docker compose up -d

docker compose logs netbird-server 2>&1 | tail -30
```

**期望：**

```text
Relay: false
Relay addresses: [rels://relay-jp.flaship.org:443 rels://relay-hk.flaship.org:443 rels://relay-tw.flaship.org:443]
```

```bash
curl -sk https://netbird.flaship.org/oauth2/.well-known/openid-configuration | head
```

### 4.5 主站防火墙

| 端口 | 改造后 |
|------|--------|
| TCP 80 / 443 | 保留（Traefik） |
| UDP 3478 | 可关闭 |

`dashboard.env` 保持：

```bash
NETBIRD_MGMT_API_ENDPOINT=https://netbird.flaship.org
NETBIRD_MGMT_GRPC_API_ENDPOINT=https://netbird.flaship.org
```

## 5. 阶段 B：区域 Relay 部署

### 5.1 DNS 与机器规划

| 域名 | 建议公网 IP / 机器 |
|------|-------------------|
| `relay-jp.flaship.org` | 日本 EC2（可与 `aws-8237-jp` / `54.95.171.5` 同机试点） |
| `relay-hk.flaship.org` | 香港 EC2 |
| `relay-tw.flaship.org` | 台湾 EC2（可与 `tw-office` 同区域） |

### 5.2 边缘目录与文件

在每台区域 VM：

```bash
mkdir -p /opt/netbird-edge && cd /opt/netbird-edge
```

#### `relay.edge.env`（日本示例）

```bash
NB_LOG_LEVEL=info
NB_LISTEN_ADDRESS=:443
NB_EXPOSED_ADDRESS=rels://relay-jp.flaship.org:443
NB_AUTH_SECRET=<主站 config.yaml authSecret，一字不差>

NB_LETSENCRYPT_DOMAINS=relay-jp.flaship.org
NB_LETSENCRYPT_EMAIL=server@crabxhub.com
NB_LETSENCRYPT_DATA_DIR=/data/letsencrypt

NB_ENABLE_STUN=true
NB_STUN_PORTS=3478
NB_HEALTH_LISTEN_ADDRESS=:9000
```

香港 / 台湾：仅改 `NB_EXPOSED_ADDRESS`、`NB_LETSENCRYPT_DOMAINS`。

#### `docker-compose.edge.yml`

```yaml
services:
  netbird-relay:
    image: netbirdio/relay:${NETBIRD_VERSION:-latest}
    container_name: netbird-relay-edge
    restart: unless-stopped
    network_mode: host
    env_file:
      - relay.edge.env
    volumes:
      - relay_edge_data:/data
    logging:
      driver: json-file
      options:
        max-size: "100m"
        max-file: "2"

volumes:
  relay_edge_data:
```

仅部署 Relay 时用上表；若同机还要 Router，见 §6 合并 compose。

### 5.3 启动与验证

```bash
export NETBIRD_VERSION=0.67.1
docker compose -f docker-compose.edge.yml up -d
curl -vk https://relay-jp.flaship.org/
```

防火墙：**TCP 80、443**，**UDP 3478**。

## 6. 阶段 C：Router 修正

### 6.1 各 Peer 策略

| Peer | 网络 | 优化动作 |
|------|------|----------|
| `aws-8237-jp-router-01` | 公网 `54.95.171.5` | SG **UDP 51820**；Docker **`--network host`**；可与 relay-jp 同机 |
| `aws-8237-hk-router-01` | 公网 | SG UDP 51820 + Docker host + relay-hk |
| `aws-3009-router-01` | 新加坡 | SG + host；数据面可用 relay-sg（需独立 VM，勿占主站 443） |
| `oci-jp-router-01` | 私网 + NAT GW | 不强求 P2P；依赖 **relay-jp** 出站 |
| `tw-office-router-01` | P2P 正常 | 保持；可选 relay-tw |
| `aws-1718-my-router-01` | P2P 正常 | 保持 |

### 6.2 AWS JP：安全组

`sec-netbird-jp-router` 入站增加：

| 协议 | 端口 | 源 |
|------|------|-----|
| UDP | 51820 | `0.0.0.0/0` |

保留原有管理 IP 规则即可。

### 6.3 AWS JP：Docker Router（替代 Dashboard 默认 bridge 命令）

**停止旧容器后：**

```bash
docker stop netbird-jp-router 2>/dev/null; docker rm netbird-jp-router 2>/dev/null

docker run -d \
  --name netbird-jp-router \
  --hostname aws-8237-jp-router-01 \
  --network host \
  --privileged \
  --cap-add=NET_ADMIN \
  --cap-add=SYS_ADMIN \
  --cap-add=SYS_RESOURCE \
  --device /dev/net/tun \
  -e NB_SETUP_KEY="<Dashboard Setup Key>" \
  -e NB_MANAGEMENT_URL=https://netbird.flaship.org:443 \
  -e NB_WIREGUARD_PORT=51820 \
  -e NB_LOG_LEVEL=info \
  -v netbird-client:/var/lib/netbird \
  --restart unless-stopped \
  netbirdio/netbird:0.67.1
```

### 6.4 日本同机：Relay + Router 合并 compose

`/opt/netbird-edge/docker-compose.edge.yml`：

```yaml
services:
  netbird-relay:
    image: netbirdio/relay:${NETBIRD_VERSION:-latest}
    container_name: netbird-relay-edge
    restart: unless-stopped
    network_mode: host
    env_file:
      - relay.edge.env
    volumes:
      - relay_edge_data:/data

  netbird-router:
    image: netbirdio/netbird:${NETBIRD_VERSION:-latest}
    container_name: netbird-router-edge
    restart: unless-stopped
    network_mode: host
    env_file:
      - peer.edge.env
    cap_add:
      - NET_ADMIN
      - SYS_ADMIN
      - SYS_RESOURCE
    devices:
      - /dev/net/tun:/dev/net/tun
    sysctls:
      net.ipv4.ip_forward: "1"
      net.ipv4.conf.all.src_valid_mark: "1"
    volumes:
      - netbird_router_edge_data:/var/lib/netbird
    depends_on:
      - netbird-relay

volumes:
  relay_edge_data:
  netbird_router_edge_data:
```

`peer.edge.env`：

```bash
NB_SETUP_KEY=<Setup Key>
NB_HOSTNAME=aws-8237-jp-router-01
NB_MANAGEMENT_URL=https://netbird.flaship.org:443
NB_LOG_LEVEL=info
NB_WIREGUARD_PORT=51820
```

## 7. 阶段 D：客户端与 Dashboard 策略

### 7.1 Mac 立即操作

1. Dashboard **取消** `aws-8237-jp-router-01` 的 **`0.0.0.0/0` Exit Node**（在仍 Relayed 时禁止全网出口）。  
2. 仅保留业务所需网段路由（如 `10.2.x`、`10.121.1.0/24`、`10.20.0.0/16`）。  
3. 重连：

```bash
netbird down && netbird up
netbird status -d
```

### 7.2 DNS

- 勿将 `1.1.1.1` / `8.8.8.8` 作为全球唯一上游（国内 probe 易失败）。  
- 在 Dashboard DNS 配置国内可达上游或区域 DNS；`*.flaship.org` 可用 Custom zones。

### 7.3 版本

- 当前约 `0.67.1`，可规划维护窗口升级至 `0.71.x`（Server 与 Agent 对齐）。

### 7.4 Dashboard Docker 安装说明

弹窗中的 `docker run`（仅 `NET_ADMIN`、bridge）**不适合**公网 Routing Peer。生产以本文 **host 网络** 为准。源码位置：`dashboard/src/modules/setup-netbird-modal/DockerTab.tsx`（可选后续改版）。

## 8. 阶段 E：验收标准

在 Mac 执行：

```bash
netbird status -d
```

| 检查项 | 期望 |
|--------|------|
| Relays | `relay-jp` / `relay-hk` / `relay-tw` 均为 **Available** |
| 访问日本 | Relay 为 `relay-jp.*` 或 **P2P**，端点含 `54.95.171.5:51820` |
| 访问台湾 | **P2P**，延迟约 50–80ms |
| 主站 | 日志 `Relay: false` |
| Exit | 无长期 `0.0.0.0/0` → Relayed Peer |
| DNS Events | 减少 `All upstream servers failed` |

## 10. 回滚方案

```bash
cd ~/netbird
cp config.yaml.bak.YYYYMMDD config.yaml
# 恢复 docker-compose.yml 中 3478:3478/udp
docker compose down && docker compose up -d
```
